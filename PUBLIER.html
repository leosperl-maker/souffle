Obtenir le lien Windows

Quinze minutes, une seule fois. Ensuite, un lien à transférer.

Une application Windows pèse environ 100 Mo — trop pour être envoyée par message. La solution : laisser GitHub la fabriquer et l'héberger. Vous déposez le code une fois, leur infrastructure compile sur une vraie machine Windows, et vous obtenez une page de téléchargement publique dont vous transmettez simplement l'adresse.

Tout se fait dans le navigateur. Aucune ligne de commande.

Étape par étape

1

Créez un dépôt

Sur github.com/new — créez un compte si nécessaire, c'est gratuit. Nommez-le souffle. Laissez-le Public : c'est ce qui rendra le lien de téléchargement accessible sans compte à la personne à qui vous l'enverrez.

Ne cochez rien d'autre — ni README, ni .gitignore, ni licence. Cliquez sur Create repository.

2

Déposez les fichiers

Sur la page qui s'affiche, cliquez sur uploading an existing file.

Décompressez le zip du projet sur votre bureau, ouvrez le dossier obtenu, sélectionnez tout son contenu (Cmd+A), et faites-le glisser dans la zone de dépôt de la page.

Attendez que la liste se remplisse — une trentaine de fichiers — puis cliquez sur Commit changes en bas.

Glissez le contenu du dossier, pas le dossier lui-même. Et si vous voyez apparaître node_modules ou dist dans la liste, retirez-les : ce sont des fichiers temporaires, inutiles et très lourds.

3

Laissez la machine travailler

Le dépôt contient déjà les instructions de compilation. Dès que vos fichiers sont déposés, GitHub démarre une machine Windows et construit l'installateur tout seul.

Cliquez sur l'onglet Actions en haut du dépôt pour suivre. Un point orange signifie « en cours », une coche verte « terminé ». Comptez cinq à huit minutes la première fois.

4

Récupérez le lien

Une fois la coche verte obtenue, allez dans Releases, dans la colonne de droite de la page d'accueil du dépôt. Vous y trouverez Souffle pour Windows — version 1 avec le fichier Souffle-Installateur-0.1.0.exe.

Clic droit sur ce fichier → Copier l'adresse du lien. C'est ce lien que vous envoyez. La personne le télécharge et double-clique : rien d'autre à faire de son côté.

Pour les versions suivantes : modifiez un fichier depuis GitHub, ou redéposez-en une version corrigée, et une nouvelle Release se crée automatiquement. Vous pouvez aussi relancer la construction à la main depuis l'onglet Actions, bouton Run workflow.

Ce que verra la personne

Elle télécharge un fichier .exe, le double-clique, et Windows affiche un avertissement bleu : « Windows a protégé votre ordinateur ». C'est systématique pour toute application non signée par un certificat commercial — un certificat coûte environ 300 € par an et n'est utile que pour une diffusion large.

Elle clique sur Informations complémentaires puis Exécuter quand même. L'installation se fait ensuite toute seule, Souffle démarre, et une icône apparaît près de l'horloge. Le mode d'emploi complet est dans LISEZ-MOI.html.

Prévenez-la de cet avertissement à l'avance : c'est le seul moment où elle risque de renoncer.

Si vous préférez le terminal

Trois commandes depuis le dossier du projet, au lieu des étapes 1 et 2 :

git init -b main
git add .
git commit -m "Souffle"
gh repo create souffle --public --source=. --push

La dernière ligne utilise l'outil gh de GitHub. Sans lui, créez le dépôt sur le site puis git remote add origin … et git push -u origin main.

Et pour macOS ?

Sur votre propre Mac, une seule commande depuis le dossier du projet produit un .dmg dans dist/ : 

npm run dist:mac

Même avertissement de sécurité au premier lancement : clic droit sur l'application → Ouvrir plutôt qu'un double-clic, une seule fois.
